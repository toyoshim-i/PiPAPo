# Intel 8086 (ia16) Target

Architecture-specific reference for the PPAP ia16 port (8086 real mode,
segmented memory).  Current target is PC/XT (`pcxt`) running on QEMU
(`qemu-system-i386`).

See also [V30 8080 emulation support](../proposals/v30_support.md).

---

## 1. Architecture Overview

| Aspect | ARM Cortex-M0+ | Motorola 68000 | Intel 8086 (ia16) |
|--------|----------------|----------------|-------------------|
| ISA | 16-bit Thumb-1 (RISC) | 32-bit CISC | 16-bit CISC |
| Word size | 32-bit | 32-bit | 16-bit |
| Endianness | Little-endian | Big-endian | Little-endian |
| Registers | r0-r12, SP, LR, PC, xPSR | d0-d7, a0-a6, a7/SP, PC, SR | AX, BX, CX, DX, SI, DI, BP, SP, CS, DS, ES, SS, IP, FLAGS |
| Callee-saved | r4-r11 | d2-d7, a2-a6 | SI, DI, BP, BX, ES |
| Caller-saved | r0-r3, r12, LR | d0-d1, a0-a1 | AX, CX, DX |
| Stack pointer | MSP/PSP (dual) | USP/SSP (dual) | SS:SP (single, SS switchable) |
| Privilege | Handler/Thread mode | Supervisor/User mode | None (real mode) |
| Syscall | `svc 0` | `trap #0` | `int $0x30` |
| Timer interrupt | SysTick (built-in) | External timer IC | 8253/8254 PIT (IRQ 0) |
| Context switch | PendSV (deferred) | Direct in timer ISR | Direct in timer ISR |
| MMU/MPU | 4-region MPU | None (68000) | None (real mode) |
| Address space | 32-bit, XIP from flash | 24-bit (16 MB) | 20-bit (1 MB), segmented |
| HW exception frame | Auto-push {r0-r3,r12,lr,pc,xpsr} | Auto-push {SR,PC} | Auto-push {FLAGS,CS,IP} |
| ELF machine | EM_ARM (40) | EM_68K (4) | EM_386 (3), 16-bit |
| Compiler flags | `-mthumb -mcpu=cortex-m0plus` | `-m68000` | `-march=i8086 -mtune=i8086` |

### Kernel

- **Docker:** `ppap/ia16` image bundles toolchain and QEMU

## 3. Syscall ABI

PPAP uses `int $0x30` for system calls on ia16.

```
int $0x30
AX = syscall number → return value
BX = arg1
CX = arg2
DX = arg3
SI = arg4
DI = arg5
```

### INT 30h Rationale

INT 30h is unused on PC/XT (INT 00h–07h are CPU exceptions, INT 08h–0Fh
are 8259A IRQs, INT 10h–1Ah are BIOS services, INT 20h–2Fh are DOS).
INT 30h is safely outside all standard ranges.

### Argument Count

ia16 supports 5 syscall arguments (BX, CX, DX, SI, DI).  User-space
DS (segment register) is captured by `trap.S` for pointer resolution
but is not a general-purpose argument slot.

### Pointer Resolution

User pointers are segment-relative offsets.  `trap.S` captures the
user's DS (= SS = process segment) and the kernel resolves pointers
through `arch_user_ptr_to_page()` which converts `user_ds:offset`
to a `page_id_t + offset` pair.

## 4. Context Switch

### ISR/Syscall Frame

The i16 port uses a **split frame** design:

- **User stack** (SS=proc_seg): GP registers (18 bytes) + hardware
  FLAGS/CS/IP (6 bytes) = 24-byte frame.
- **Kernel stack** (SS=0): only user_SS:user_SP (4 bytes) saved.
- `pcb->sp` points to the kernel stack entry.

On exit, user SS:SP is restored and IRET pops from the user stack.

### Per-Process Kernel Stacks

User processes run with `SS=proc_seg` so ia16-elf-gcc's SS-relative
data access hits the process segment.  The kernel runs with `SS=0`.

- **8 kernel stacks** at 0xE380–0xFFFF in DS=0.  Slot 0 (idle) gets
  128 bytes; slots 1-7 get 1 KB each.
- **`i16_current_ksp`** global holds the current process's kernel
  stack top.  Updated on context switch.  ISR entry uses the 8086
  SS-load interrupt inhibit to set SS:SP atomically.
- **PID 0 detection**: if SS=0 on ISR entry (kernel context), the
  stack switch is skipped.

### Timer-Driven Switch

The INT 08h timer ISR checks `i16_switch_pending`.  If set, it saves
the current process's GP+IRET frame on the user stack, saves user
SS:SP on the kernel stack, switches `i16_current_ksp` to the target
process, and restores from the new kernel/user stacks.

### vfork / execve on Split-Frame ABI

With the split-frame layout, `vfork()` does not copy the child's user
stack.  The child shares the parent's user stack.

- **Parent frame save**: `sys_vfork()` copies the parent's 24-byte
  user resume frame onto the parent's kernel stack.  AX slot patched
  with `child_pid`.
- **Child return value**: shared user frame's AX patched to `0`.
- **Parent restore**: every user-resume path (trap return AND timer-ISR
  return) calls `i16_vfork_restore_frame()` before the final `iret`.
- **`execve()` handoff**: `elf16_loader` records `exec_user_ss` /
  `exec_user_sp` in the PCB.  Trap return path rebuilds the kernel-stack
  entry from those fields.

## 5. Segmented Memory Model

This is the most significant architectural difference from ARM and m68k.

### The Segment Model

Physical address = `segment * 16 + offset`.  All pointers are implicitly
relative to a segment register (CS for code, DS for data, SS for stack,
ES for extra).  A "far pointer" is a 32-bit `segment:offset` pair that
can address any byte in the 1 MB space.

### ia16-elf-gcc Segment Register Behaviour

The small-model compiler uses **SS for all data access** (`%ss:` prefix
on every memory operand).  DS is used as a **scratch register** — the
compiler freely loads arbitrary values into DS.  DS is NOT used for
actual memory reads/writes.

This means:
- SS must always point to the shared data segment (SS=0 in kernel)
- DS can contain any value — it does not affect data access
- Assembly code must use `%ss:` for data access, not rely on DS

### Kernel Segments

All kernel modules share **SS=0** for data access.  Each module's code
lives in its own code segment (separate CS).  Cross-module calls use
`lcall`/`lret` stubs — SS stays unchanged, so pointer arguments work
without serialization.

```
Segment     Contents
────────    ─────────────────────────────
CS=0x1000   Core .text (loaded once into its own 64 KB segment)
CS=????     VFS code: vfs, namei, romfs, tmpfs, devfs, procfs, ufs
SS=0        Shared data: each module's .rodata + .data + .bss
            (no .text duplicate), per-process kernel stacks
```

The core binary is split into two flat files at link time
(`/boot/kernel_text` for `.text`, `/boot/kernel_data` for
`.rodata`+`.data`).  Stage2 loads `kernel_text` to CS=0x1000:0x0000
(the only copy) and `kernel_data` to DS=0:0x0600.  `.rodata` stays in
DS=0 because ia16-elf-gcc's small model addresses read-only data via
`%ss:` — only `.text` (executed via CS) can leave the shared segment.

A **segment manager** (`src/kernel/common/seg.h`/`seg.c`) tracks each
module's code segment base at runtime.

### Page Allocator Adaptation

The page allocator uses `page_id_t` (16-bit index) to identify pages,
not `void *` pointers.  This is essential on i16 where `void *` is
16-bit and cannot represent page-pool addresses above 64 KB.

- 4 KB page = 256 paragraphs (0x100 segment units)
- 1 MB address space / 4 KB = 256 possible pages
- Minus kernel, BIOS, video memory -> ~200 usable pages

`mm_page_linear(id)` returns the 32-bit linear address of a page.
Data on pages is accessed via `mm_page_read()`/`mm_page_write()`.

The broader memory management refactoring is described in
[`memory_management.md`](../kernel/memory_management.md).

## 6. Module System and Far Calls

Each module's code must fit in 64 KB.  Cross-module calls use assembly
stubs to bridge code segments:

```
Core segment (CS=0x1000):        VFS segment (own CS):
──────────────────────────       ──────────────────────────
caller()                         vfs_init_entry:
  call mod_vfs.init()              call vfs_init   ; near
  ; near call to ->              vfs_init:
vfs_init_caller_stub:                ...  (SS=0, shared data)
  pop ret_ip                       ret            ; near
  push CS; push ret_ip            lret  <-- far return
  ljmp *[vfs_fptrs + 0] -- far -->
──────────────────────────       ──────────────────────────
```

The VFS header at offset 0 in the VFS segment contains a magic word
(0x5646 = "VF"), entry count, and a table of entry offsets.
`target_early_init()` reads this header and patches both the core's
`vfs_fptrs[]` and the VFS's `core_fptrs[]` with far pointer pairs
(offset, segment).

See [kernel_modules.md](../kernel/kernel_modules.md) for the module
system design.

## 7. User-Space Details

### Memory Model

User processes use the tiny-model invariant `CS = DS = SS = ES = proc_seg`.
Any near pointer reaches the 64 KB range
`[proc_seg << 4 .. (proc_seg << 4) + 0x10000)`.

- `execve` allocates 16 contiguous 4 KB pages.
- `proc_seg = mem_region_page_linear(base_id) >> 4`.
- Pages 0..14 are image / brk / mmap; page 15 is the user stack.

### user_to_page Pointer Resolution

All user-space pointer arguments are resolved to a **page_id + offset
pair** before access:

```c
typedef struct { page_id_t page; uint16_t off; } user_page_ref_t;

static inline user_page_ref_t user_to_page(page_id_t base,
                                           uint32_t user_off) {
  user_page_ref_t ref;
  ref.page = base + (page_id_t)(user_off / PAGE_SIZE);
  ref.off  = (uint16_t)(user_off % PAGE_SIZE);
  return ref;
}
```

I/O syscalls pass `page_id_t` through the VFS API.  Path arguments are
copied into a kernel stack buffer.  Struct-output syscalls fill a
kernel-stack struct and write via `mem_region_page_write`.

### brk / mmap Rules

- `sys_brk` uses segment-relative offsets, not flat linear addresses.
- `sys_brk` may only grow below page 15 (collision check with mmap).
- `sys_mmap2` / `sys_munmap` stay inside the owned segment.
- Anonymous mmap pages are cleared before exposure to user space.

### Why Generic page_alloc Is Wrong for User Memory on i16

`mm_page_alloc()` picks high free pages to preserve low contiguous runs.
On i16, a high global page is often outside the process segment's 64 KB
window.  User memory must come from the exec-time contiguous allocation.

## 8. PC/XT Target (`pcxt`)

### Hardware

| Item | Address/IRQ | PPAP Use |
|------|-------------|----------|
| RAM | 0x00000-0x9FFFF (640 KB) | Kernel + user pages |
| Video RAM | 0xB0000-0xB7FFF (MDA) / 0xB8000-0xBFFFF (CGA) | Text display |
| BIOS ROM | 0xF0000-0xFFFFF (64 KB) | INT 10h, INT 13h, INT 16h |
| 8259A PIC | 0x20-0x21 | Interrupt controller |
| 8253/8254 PIT | 0x40-0x43 | Timer (100 Hz tick) |
| 8250 UART | 0x3F8-0x3FF (COM1), IRQ 4 | Serial console |
| 8042 KBC | 0x60, 0x64 | Keyboard |
| FDC | 0x3F0-0x3F7, IRQ 6 | Floppy block driver |
| DMA (8237A) | 0x00-0x0F | FDC DMA channel 2 |

### BIOS Services

The PC BIOS remains mapped at 0xF0000 throughout execution:

| BIOS Call | INT | Purpose |
|-----------|-----|---------|
| Video output | INT 10h (AH=0Eh) | Teletype character output |
| Disk I/O | INT 13h (AH=02h) | Read floppy sectors (CHS) |
| Keyboard | INT 16h (AH=00h/01h) | Read key / check status |
| Equipment | INT 11h | Detect installed hardware |
| Memory size | INT 12h | Conventional memory size in KB |

### Interrupt Controller (8259A PIC)

| IRQ | INT | Source |
|-----|-----|--------|
| 0 | 08h | PIT timer |
| 1 | 09h | Keyboard |
| 2 | 0Ah | Cascade (XT: unused) |
| 3 | 0Bh | COM2 |
| 4 | 0Ch | COM1 |
| 5 | 0Dh | LPT2 / hard disk |
| 6 | 0Eh | FDC |
| 7 | 0Fh | LPT1 |

EOI: `outb(0x20, 0x20)` after each ISR.

### Timer (8253/8254 PIT)

```
PIT clock input:  1,193,182 Hz
Divisor for 100 Hz:  11932  (0x2E9C)
    1,193,182 / 11932 = 100.006 Hz
```

Timer init is deferred to `target_post_mount` because INT 08h
replacement breaks BIOS floppy motor control (INT 13h depends on the
original BIOS timer handler for motor timeout).

**BIOS Timer / Floppy Coupling:**

- INT 08h cadence matters: chaining the BIOS handler at reduced rate
  causes INT 13h floppy reads to fail.
- IRQ 6 must remain unmasked for FDC completion.
- Current policy: defer `timer_init()` until after initial floppy-backed
  exec of `/sbin/init`; preserve BIOS PIC mask; chain BIOS INT 08h on
  every tick; return `-EIO` on BIOS read failure.

### Boot Sequence

1. BIOS loads sector 0 -> 0x7C00 (stage1).  Prints "Pi".
2. Stage1 loads 8 sectors -> 0xC000 (stage2).  Prints "PA".
3. Stage2 reads UFS:
   - loads `/boot/kernel_text` -> CS=0x1000:0x0000 (.text only)
   - loads `/boot/kernel_data` -> DS:0x0600 (.rodata + .data)
   - loads `/boot/kernel_vfs` -> VFS CS (after core text)
   - loads `/boot/kernel_vfs_data` -> DS:0xB600
   - computes page pool start; writes `mod_info_t` at 0x0500
   - far-jumps to 0x1000:0x0000 (_start in boot.S, .text VMA base)
4. Kernel prints "Po booting... [pcxt]" — completing "PiPAPo booting...".
5. `target_early_init()`: UART + BIOS console, reads mod_info, patches
   far-call tables.
6. `mm_init()` -> `proc_init()` -> `vfs_init()` (via far call).
7. `target_late_init()`: registers floppy block device, mounts UFS root.
8. `target_post_mount()`: installs PIT timer (deferred).
9. `sched_start()`: enables interrupts, enters idle loop.

### Memory Map

```
DS=0 (shared data segment, also CS for stage1/stage2 boot phase):
0x00000-0x003FF  IVT (256 vectors x 4 bytes)
0x00400-0x004FF  BIOS Data Area
0x00500-0x005FF  mod_info_t (written by stage2)
0x00600          Core .rodata + .data + .bss (~7 KB today)
  ~0x02200       (free)
0x0B600-0x0E37F  VFS .rodata + .data + .bss (~10 KB)
  ~0x0E37F       (free)
0x0E380          kernel_stack[0] (128 B, idle)
0x0E400          kernel_stack[1] (1 KB)
0x0E800          kernel_stack[2] (1 KB)
  ...            kernel_stack[3-6] (1 KB each)
0x0FC00          kernel_stack[7] (1 KB)
0x0FFFF          End of kernel stacks

Code segments (loaded by stage2 to dedicated CS regions):
0x10000          Core .text (CS=0x1000:0x0000) — THE copy, no DS=0 dup
  ~0x19000       VFS .text (own CS)
  ~0x22000       (page-aligned)

Page pool (far-pointer access via page_id_t):
0x2????-0x9FBFF  User pages
0x9FC00-0x9FFFF  EBDA (1 KB, preserved)
0xA0000-0xBFFFF  Video RAM
0xC0000-0xFFFFF  ROM / BIOS
```

### Size Constraint

Two independent budgets:

- **Core CS**: `.text` ≤ 64 KB (own segment, currently ~36 KB used).
- **Core DS=0**: `.rodata + .data + .bss` ≤ 45 056 B between 0x0600 and
  0xB600 (currently ~7 KB used).

VFS data at 0xB600 must end before 0xE380 (own ~11.6 KB budget).

| Component | Size | Address |
|-----------|------|---------|
| Core .text | ~36 KB | CS=0x1000:0x0000 |
| Core .rodata | ~1.3 KB | DS=0:0x0600 |
| Core .data + .bss | ~5.8 KB | DS=0:0x0B26 |
| VFS .rodata + .data + .bss | ~10 KB | DS=0:0xB600 |
| Kernel stacks | 7.1 KB | 0xE380-0xFFFF |
| VFS .text | ~34 KB | (separate far CS) |
| Page pool | ~500 KB | after code segments |

### Out of Scope

- Graphics modes (VGA/EGA/CGA graphics, VESA)
- Sound (PC speaker, Sound Blaster, AdLib)
- 80286/80386 protected mode — kernel runs entirely in real mode
- Network drivers (NE2000, etc.)
- GPT partitioning — MBR only

## 9. Key Differences from ARM and m68k

| Aspect | ARM / m68k | ia16 |
|--------|-----------|------|
| Pointer size | 32-bit | 16-bit (near), 32-bit (far) |
| Address space | Flat | Segmented (64 KB per segment) |
| Data access | Via DS (m68k) or direct (ARM) | Via SS (compiler quirk) |
| Kernel data sharing | Single address space | SS=0 shared across modules |
| Cross-module calls | Direct function pointers | Far-call stubs (`lcall`/`lret`) |
| Page addressing | `void *` | `page_id_t` (16-bit index) |
| User memory | Single alloc per page | 16-page contiguous segment |
| Syscall mechanism | `svc`/`trap` | `int $0x30` |
| ISR frame | Auto-pushed by hardware (8/6 bytes) | FLAGS+CS+IP (6 bytes) |
| Stack switching | Hardware (MSP/PSP) or USP/SSP | Manual SS:SP swap in ISR |
