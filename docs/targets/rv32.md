# RISC-V RV32 Targets

Architecture-specific reference for the PPAP RISC-V port.  Current targets
are QEMU virt (`qemu_rv32`) and Raspberry Pi Pico 2 RISC-V (`pico2rv`,
RP2350 Hazard3 cores).

---

## 1. Architecture Overview

| Aspect | Detail |
|--------|--------|
| ISA | RV32IMAC (Integer + Multiply + Atomic + Compressed) |
| Targets | QEMU virt (`qemu_rv32`), Raspberry Pi Pico 2 RISC-V (`pico2rv`) |
| Endianness | Little-endian |
| Word size | 32-bit |
| Registers | x0-x31 (x0=zero, x1=ra, x2=sp, x3=gp, x4=tp) |
| Callee-saved | s0-s11 (x8-x9, x18-x27) |
| PCB_SP_OFFSET | 48 |
| Syscall | `ecall` from U-mode (a7=number, a0-a5=args) |
| Timer | CLINT mtime/mtimecmp (QEMU) or SIO mtime (RP2350) |
| Context switch | Timer ISR checks `riscv_switch_pending`, calls `riscv_do_switch` |
| FPU | None (soft-float, ilp32 ABI) |
| Privilege | User processes in U-mode, kernel in M-mode |
| PMP | Entry 0: full RWX for U-mode (no protection yet) |
| Stack isolation | mscratch-based kernel/user stack split |
| Multi-core | Single-core (Phase RV-6 planned for dual-core) |

## 2. Toolchains

### Kernel

- **Compiler:** `riscv32-unknown-elf-gcc` 15.1.0 (prebuilt, Pico SDK tools)
- **ABI:** ilp32 (soft-float)

### User-space (ePIC)

All user-space binaries use lowRISC's ePIC (Embedded PIC) LLVM fork:

- **Compiler:** `clang-16` (lowRISC ePIC fork) with `-fepic`
- **Linker:** `ld.lld` (lowRISC fork)
- **ABI:** ilp32 (soft-float)
- **Binary type:** ET_DYN (PIE) with GP-relative data access
- **Relocations:** `R_RISCV_RELATIVE` in `.rela.dyn`, applied by the
  kernel ELF loader

musl-linked binaries (busybox, rogue) use the ePIC linker script
(`libc_riscv_epic.ld`) and a patched CRT (`crt_arch.h` overlay).

### GCC 15 / C23 compatibility

GCC 15 defaults to `-std=gnu23` (C23).  Legacy K&R code that passes
arguments through `()` function pointers fails.  Fix: compile with
`-std=gnu11` (applied in `build_rogue.sh` and busybox config).

## 3. ePIC and XIP

### Model: XIP text + SRAM rodata + SRAM data

ePIC uses GP-relative addressing for all data access including rodata.
With XIP, text executes from romfs but rodata and data must be in SRAM
so the GP register can reach both.

The ePIC linker script (`libc_riscv_epic.ld`) produces three segments:

| Segment | Flags | Contents | Location |
|---------|-------|----------|----------|
| text | R+X | `.text` | XIP from romfs |
| rodata | R | `.rodata`, `.rela.dyn`, `.dynamic`, `.dynsym`, `.hash` | SRAM |
| data | R+W | `.data.rel.ro`, `.sdata`, `.data`, `.bss` | SRAM |

The rodata and data segments are at contiguous virtual addresses.  The
ELF loader allocates them in a single SRAM block.  Future PMP can mark
the rodata region read-only.

### GP register

The kernel sets `gp = data_base - data_va` in the initial trap frame,
where `data_va` is the virtual address of the rodata segment (the first
non-text segment).  All GP-relative access uses `gp + link_addr` to
compute the runtime address.

The musl CRT overlay (`crt_arch.h`) does **not** touch GP — the
kernel-provided value is used as-is.

### ELF loader relocation

`riscv_resolve_addr()` resolves link-time addresses for
`R_RISCV_RELATIVE` relocations:

- `link_addr >= data_va` → SRAM: `data_base + (link_addr - data_va)`
- `link_addr < data_va` → text (XIP): `text_base + (link_addr - text_vaddr)`

### musl CRT

The musl CRT overlay (`third_party/patches/musl/overlay/arch/riscv32/crt_arch.h`)
makes two changes from upstream:

1. Removes `lla gp, __global_pointer$` — GP is set by the kernel.
2. Passes `_DYNAMIC = NULL` — the kernel handles all relocations,
   so musl's self-relocation must be skipped for XIP.

## 4. Trap Handling

All traps go through `mtvec` (direct mode):

```
_trap_vector → _trap_entry (trap.S)
    │
    ├── mscratch swap (sp ↔ mscratch)
    │     ├── MPP=0 (from U-mode): swap correct, save user sp
    │     └── MPP=3 (nested M-mode): undo swap
    │
    ├── Save registers + restore kernel GP
    │
    ├── Exception path
    │     ├── ecall → syscall_dispatch
    │     └── other → riscv_exception_handler (re-entry guard + backtrace)
    │
    └── Interrupt path
          └── timer (cause=7) → riscv_timer_handler → sched_timer_tick
```

### Trap Frame

144-byte trap frame (36 words): x1, x3-x31, mepc, mstatus, user_sp,
plus padding.

### Kernel GP Restore

After saving the user GP, the trap entry loads the kernel's
`__global_pointer$` so GP-relative access in kernel code works
correctly.  Without this, the kernel would use the user process's GP
and read/write globals at wrong addresses.

### Kernel/User Stack Split (mscratch)

User processes run in U-mode with their own user stack page (tracked
at `user_pages[USER_PAGES_MAX - 1]`).  The kernel stack (`stack_page`)
is separate.

- **Trap entry:** `csrrw sp, mscratch, sp` swaps user sp with kernel
  stack top.  `mstatus.MPP` distinguishes U-mode from M-mode.
- **Trap exit:** if `TF_USER_SP != 0`, returning to U-mode — restore
  user sp via `csrrw`.
- **Context switch:** `riscv_do_switch` saves/restores trap frame on
  kernel stack.  `mscratch` is updated for the new process.

### vfork

The child gets its own kernel stack (copy of parent's) and a separate
user stack copy (same pattern as m68k, via `vfork_copy_user_stack`
shared helper).  TF_USER_SP in the child's trap frame is patched to
the new user stack.

### Syscall Restart

`svc_restart` rewinds `mepc` by 4 and restores the original `a0`,
causing the `ecall` to re-execute on return.

### Exec Pending

`exec_pending` reloads SP from `current->sp` and updates `mscratch`
from `current->kernel_sp`, then frees the old stack via
`exec_free_old_stack` (deferred free, shared with m68k).

## 5. QEMU Target (`qemu_rv32`)

| Parameter | Value |
|-----------|-------|
| Machine | `-M virt -bios none` |
| UART | NS16550A at `0x10000000` (polled) |
| Timer | CLINT at `0x02000000` |
| RAM | `0x80000000` (1 MB page pool, 242 pages) |

Custom string functions (`memcpy`, `strlen`, etc.) are used because the
Pico SDK toolchain generates Zcb instructions not supported by QEMU 8.x.

---

## 6. RP2350 Target (`pico2rv`)

| Parameter | Value |
|-----------|-------|
| CPU | RP2350 Hazard3 RISC-V cores (RV32IMAC + Zcb/Xh3bm/Xh3power) |
| UART | PL011 at `0x40070000` (polled) |
| Timer | SIO mtime at `0xD0000000` + offsets |
| Flash | 4 MB QSPI via XIP (QMI), FLASH_KERNEL = 168 KB |

### Boot Sequence

1. RP2350 bootrom selects RISC-V cores
2. Watchdog disabled in `boot.S` (RP2350-specific)
3. `bootrom_state_reset(GLOBAL_STATE)` for hardware init
4. `clock_init_pll` runs from `.ramfunc` section (XIP cache issue after
   `bootrom_state_reset`)

---

## 7. Known Issues

- **No PMP protection:** user processes can access kernel memory; PMP
  configuration is planned for a future phase
- **trace tool:** vfork in the trace tool crashes on RISC-V (deeper
  context switch issue, not related to ePIC)
