# RISC-V RV32 Targets

Architecture-specific reference for the PPAP RISC-V port. Current targets
are QEMU virt (`qemu_rv32`) and Raspberry Pi Pico 2 RISC-V (`pico2rv`,
RP2350 Hazard3 cores).

---

## 1. Architecture Overview

| Aspect | Detail |
|--------|--------|
| ISA | RV32IMAC (Integer + Multiply + Atomic + Compressed) |
| Targets | QEMU virt (`qemu_rv32`), Raspberry Pi Pico 2 RISC-V (`pico2rv`) |
| Endianness | Little-endian |
| Word size | 32-bit |
| Registers | x0-x31 (x0=zero, x1=ra, x2=sp, x3=gp) |
| Callee-saved | s0-s11 (x8-x9, x18-x27) |
| PCB_SP_OFFSET | 48 |
| Syscall | `ecall` (a7=number, a0-a5=args) |
| Timer | CLINT mtime/mtimecmp (QEMU) or SIO mtime (RP2350) |
| Context switch | Timer ISR checks `riscv_switch_pending`, calls `riscv_do_switch` |
| FPU | None (soft-float, ilp32 ABI) |
| MPU | PMP (8 regions, not yet implemented) |
| Multi-core | Single-core (Phase RV-6 planned for dual-core) |

## 2. Toolchains

### Kernel

- **Compiler:** `riscv32-unknown-elf-gcc` (bare-metal, shipped with Pico SDK)
- **ABI:** ilp32 (soft-float)

### User-space (current)

- Same bare-metal `riscv32-unknown-elf-gcc` toolchain
- No `-pie` support; uses `-fPIC` with static linking

### User-space (planned)

- **Compiler:** `riscv32-unknown-linux-gnu-gcc` (built from source)
- **Build flags:** `--with-abi=ilp32` for soft-float PIC libgcc
- The Linux toolchain is needed for `-pie` support (proper GOT-based PIC)

## 3. PIC / XIP Limitation

**This is a fundamental architectural difference from ARM and affects memory
usage significantly.**

- RISC-V `-fPIC` generates `auipc` (PC-relative) for ALL symbol references,
  including writable statics and local data
- Unlike ARM's `-msingle-pic-base -mpic-register=r9` (GOT-indirect for all
  data), RISC-V has no way to force GOT indirection for local/static symbols
- **Consequence:** user-space text+data must be loaded contiguously in SRAM
  (no XIP text separation like ARM)
- The ELF loader copies both `.text` and `.data` segments to SRAM pages so
  PC-relative offsets remain correct

### RAM Cost (pages, out of 116 on RP2350)

| Binary | Pages |
|--------|-------|
| push | 6 |
| busybox | 48 |
| hello | 1 |

### Future: `-pie` with Linux toolchain

- `-pie` flag (Linux toolchain only) generates GOT entries for global
  symbols, which could enable partial XIP in future
- `--emit-relocs` preserves `R_RISCV_32` relocations for function pointer
  table fixups (e.g. busybox `applet_main[]`)
- GOT entries also need patching (not covered by `--emit-relocs`)

## 4. Trap Handling

All traps go through `mtvec` (direct mode):

```
_trap_vector → _trap_entry (trap.S)
    │
    ├── Exception path
    │     ├── ecall → syscall_dispatch
    │     └── other → riscv_exception_handler
    │
    └── Interrupt path
          └── timer (cause=7) → riscv_timer_handler → sched_timer_tick
```

### Trap Frame

128-byte trap frame (32 words): x1, x3-x31, mepc, mstatus.

### Syscall Restart

The `svc_restart` flag rewinds `mepc` by 4 and restores the original `a0`,
causing the `ecall` instruction to re-execute on return.

### Exec Pending

The `exec_pending` flag reloads SP from `current->sp` before returning
from the trap, allowing `execve` to set up a fresh stack.

## 5. QEMU Target (`qemu_rv32`)

| Parameter | Value |
|-----------|-------|
| Machine | `-M virt -bios none` |
| UART | NS16550A at `0x10000000` (polled) |
| Timer | CLINT at `0x02000000` |
| RAM | `0x80000000` (512 KB used) |

**Note:** Requires custom string functions (`memcpy`, `strlen`, etc.)
because the Pico SDK toolchain generates Zcb instructions not supported
by QEMU 8.x.

---

## 6. RP2350 Target (`pico2rv`)

| Parameter | Value |
|-----------|-------|
| CPU | RP2350 Hazard3 RISC-V cores (RV32IMAC + Zcb/Xh3bm/Xh3power) |
| UART | PL011 at `0x40070000` (polled) |
| Timer | SIO mtime at `0xD0000000` + offsets |
| Flash | 4 MB QSPI via XIP (QMI) |

### Boot Sequence

1. RP2350 bootrom selects RISC-V cores
2. Watchdog disabled in `boot.S` (RP2350-specific)
3. `bootrom_state_reset(GLOBAL_STATE)` for hardware init
4. `clock_init_pll` runs from `.ramfunc` section (XIP cache issue after
   `bootrom_state_reset`)

## 8. Known Issues

- **Double-free on process exit:** zombie guard in `sys_exit` mitigates on
  QEMU; needs verification on hardware
- **`ps` out of memory:** needs more heap pages or mmap
- **No XIP text separation:** fundamental RISC-V PIC limitation
  (see section 3)
- **Zcb instruction incompatibility:** Hazard3 supports Zcb, but QEMU 8.x
  does not; custom string functions are required for the QEMU target
